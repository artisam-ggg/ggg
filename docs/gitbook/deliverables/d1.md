# D1 — Deadline-enforced escrow

## SOW commitment

Add a settlement deadline and a permissionless refund path for a tournament that has neither been finalized nor cancelled. The SOW names the intended function `claim_refund_after_deadline()` and also requires failure-path testing before the deadline.

## Implemented contract behavior

The current escrow ABI implements the deadline-refund outcome through `claim_refund(player)`, rather than a literal `claim_refund_after_deadline()` entrypoint. The contract stores `settlement_deadline` during construction, rejects a deadline that is not in the future or exceeds the configured maximum horizon, and exposes the deadline through `get_tournament()` and `get_settlement_deadline()`.

For an active tournament, `claim_refund` allows the registered player to be paid after the inclusive deadline; cancellation enables immediate individual claims. The contract source comments and regression matrix describe the call as permissionless for the caller while payment remains directed to the registered player. This is an implementation/behavior mapping to the SOW goal; it is not a claim of literal method-name equality.

## Testnet event interpretation

The public Testnet event stream for the linked contract records three `registered` events followed by the two successful `refund_claimed` events above. It records no `cancelled` or `finalized` event in the retained query window. The public source permits a refund for an active, non-cancelled tournament only after its inclusive settlement deadline; cancellation would emit `cancelled`. Together, the event sequence and source support the conclusion that these are deadline-route refunds.

This is a source-and-event inference, not a replacement for every D1 acceptance check: successful events cannot prove that an earlier, pre-deadline call was rejected.
