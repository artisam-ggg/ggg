# D1 — Deadline-enforced escrow

## SOW commitment

Add a settlement deadline and a permissionless refund path for a tournament that has neither been finalized nor cancelled. The SOW names the intended function `claim_refund_after_deadline()` and also requires failure-path testing before the deadline.

## Implemented contract behavior

The new escrow WASM exposes `claim_refund_after_deadline(player)` for the SOW's named deadline-only path and retains `claim_refund(player)` for the app's existing cancellation and deadline paths. The contract stores `settlement_deadline` during construction, rejects a deadline that is not in the future or exceeds the configured maximum horizon, and exposes the deadline through `get_tournament()` and `get_settlement_deadline()`. Earlier deployed instances retain their original ABI.

For an active, unfinished tournament, `claim_refund_after_deadline(player)` allows a permissionless caller to pay the registered player at or after the inclusive deadline. It rejects cancelled tournaments; the preserved `claim_refund(player)` path still enables immediate claims after cancellation. The two methods share one-claim state and emit the same event.
